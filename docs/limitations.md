# Limitations

| # | Limitation | Impact | Status |
|---|---|---|---|
| L1 | **Customer-level leakage across the time split.** 3,864 customers have 2–3 loans (3,043 with 2, 821 with 3). A customer's loans can originate on different dates, so one loan can land in train and another in test, and both share identical `bur_*` (and `bur_pit_*`) customer-level features. | May slightly inflate test AUC, since the model has seen that customer's bureau profile during training. | A grouped split (by customer_id) was considered and deferred: it would shrink the test set and complicate the time-based framing the stack calls for (A2/A3 in `docs/assumptions.md`). Logged here instead. **Measured (sub-problem 4):** 2,070 of 4,921 test accounts (42%) belong to a customer seen in training, and AUC on those is *lower* (0.656 vs 0.684 for new customers, LightGBM primary), so no inflation is visible. The limitation stays on record. |
| L2 | **LightGBM does not outperform logistic regression** (test AUC 0.673 vs 0.676). The first run overfit (300 trees: train AUC 0.999, test 0.633); the tree count is now set by early stopping on the 2021 in-train holdout. | LightGBM is kept for its per-account SHAP drivers; in production the simpler model would be the default choice. | Documented in `docs/model_report.md` |
| L3 | **No calibration check, and no LGD or recovery data.** | Scores rank risk but are not validated probabilities, and there is no loss-severity view. | Out of scope; noted for any real use |
